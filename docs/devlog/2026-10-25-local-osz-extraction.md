# 2026-10-25 — Локальная распаковка .osz

## Цель

Начать M1 с законченной подготовки локальных карт: получить `.osu` из архивов
владельца, не распаковывая ресурсы и не меняя оригиналы. Полный M1 не завершён.

## Исходная проблема

M0 закрыт коммитами `75af7c5` и `9a31192`. Владелец добавил 12 `.osz` в
`tests/unlabeled_osu_maps/` и правило исключения в корневой `.gitignore`.
На старте из пользовательских отслеживаемых файлов изменён был только `.gitignore`.
Его изменение оставлено нетронутым и не включается в коммит этого среза.

Осмотр ZIP directory показал 33 `.osu`, до 938 entries в одном архиве.
Большинство entries — ресурсы, которые для анализа объектов не нужны.
В предоставленных `.osu` обнаружены `Mode: 0` и заголовок v14. Это наблюдение
о данном корпусе, а не доказательство поддержки произвольных карт.

## Рассмотренные решения

1. `extractall()` с сохранением исходных путей: лишние ресурсы, доверие именам,
   неявная перезапись при повторе.
2. Одноразовый скрипт: быстро, но нельзя использовать как проверяемую часть импорта.
3. Небольшой offline CLI и адаптер `zipfile`, извлекающий только `.osu`.

## Принятое решение

Вариант 3 без новых зависимостей. Файлы адресуются по checksum, ZIP-имена
сохраняются только как metadata. Заданы явные лимиты и ограничения ZIP методов.
Parser остаётся отдельным следующим шагом; extraction не заявляет валидацию
содержимого `.osu`. Контракт описан в [local-import](../architecture/local-import.md).
Новое ADR не требуется: это локальный подготовительный сценарий внутри принятых
границ модульного монолита, без нового хранилища или очереди.

## Реализация

- [osz.py](../../src/osu_skill_lab/infrastructure/osz.py): ограниченный snapshot,
  streaming checksums, выбор `.osu`, валидация entries, временный результат,
  manifest и публикация каталога через rename.
- [cli.py](../../src/osu_skill_lab/cli.py): один архив или каталог, JSON stdout/stderr,
  продолжение batch после ошибочного архива, ненулевой exit при ошибках.
- Повторный запуск сверяет manifest и фактические выходные файлы. При расхождении
  отказывает без перезаписи; переименованный исходный архив узнаётся по checksum.
- [test_osz.py](../../tests/unit/test_osz.py) и
  [test_cli.py](../../tests/unit/test_cli.py): 35 новых синтетических тестов.
- Версионируемый [tests/.gitignore](../../tests/.gitignore) исключает локальный
  корпус и в новых clones, независимо от пользовательского корневого ignore.
  Исходные карты, manifests и результаты остаются вне коммитов.

## Проблемы

- Первый Ruff нашёл вызов frozen dataclass в default-аргументе и вложенные with;
  default перенесён внутрь функции, contexts объединены.
- Тип `ZipFile.open()` — `IO[bytes]`; первоначальная аннотация `BinaryIO` оказалась
  несовместимой для mypy. Исправлена аннотация reader, suppressions не добавлялись.
- Установка CLI через `uv sync --locked --offline` прошла. Первая распаковка
  в sandbox получила WinError 5 на временных каталогах. Повтор с разрешённым
  доступом вне sandbox успешно обработал все архивы. Оставшиеся 12 пустых
  временных каталогов удалены по точному списку, после проверки абсолютных путей,
  отсутствия reparse points и содержимого.
- Проверка manifest из sandbox тоже получила отказ доступа. Побайтовая сверка
  повторена вне sandbox и завершилась успешно. Ослабление прав на каталоги
  не добавлялось как обход ограничений среды.

## Проверки

| Проверка | Фактический итог |
| --- | --- |
| `uv sync --locked --offline` | CLI установлен из существующего lock/cache, новых зависимостей нет |
| `uv lock --check --offline` | Актуален, 39 packages |
| `ruff check .` | All checks passed |
| `ruff format --check .` | 39 files already formatted |
| `mypy` | No issues found in 21 source files |
| `pytest tests/unit/test_osz.py tests/unit/test_cli.py` | 35 passed |
| `pytest -m "not integration"` | 56 passed, 4 deselected; 1.07s |
| `uv run --locked --offline osu-skill-lab extract-osz tests/unlabeled_osu_maps` | 12 архивов, 33 `.osu`, 12 manifests, без ошибок |
| Та же CLI-команда повторно | Для всех 12 архивов reused=true |
| Прямое сравнение выходных байтов с `ZipFile.read(member_name)` | Все 33 совпали; SHA-256 и размеры manifest совпали |

Извлечено **1 413 043 байта** `.osu`; пропущено **1 637 ZIP entries**.
Все 33 файла данного корпуса декодировались как UTF-8 с опциональным BOM,
имели заголовок `osu file format v14` и `Mode: 0`. Итог лежит в
`data/unpacked_osu_maps/<archive-sha256>/`. Исходные архивы сохранены.

Тесты проверяют лимиты, фактический streaming budget, опасные пути, duplicates,
symlink/encrypted members, неподдержанный codec, CRC-сбой второй карты,
отсутствие частичного результата, изменённый результат и повторный запуск.
Неиспользуемые assets не читаются даже при неверном CRC.
Интеграционные проверки PostgreSQL и Docker этой итерацией не повторялись:
изменён только offline-сценарий, persistence и HTTP не менялись.

## Что я узнал

Размер и число ZIP entries плохо описывают объём полезных для анализа данных:
в корпусе 1 670 entries, из них только 33 карты. Имя архива не годится для
идентичности результата. Проверка CRC выбранных members не означает проверку
всего набора ресурсов и должна описываться именно так.

## Что можно улучшить

Для будущего HTTP-upload добавить отдельные ограничения запроса и процесса;
лимит entries после чтения central directory не ограничивает память жёстко.
Операция пока локальная; гарантий очереди/worker или REST import нет.
Размеченных skill/slot labels у этих карт нет, оценки качества не проводились.

## Следующие шаги

Определить и реализовать независимый `.osu` parser: metadata, difficulty,
timing points, circles/sliders/spinners, обработка некорректных файлов,
ruleset standard и воспроизводимые синтетические fixtures. После этого —
storage abstraction, первые ORM-модели и сценарий M1 через REST.
