# Development log

Журнал содержит реальные решения, проверки и неудачи. Не подменяет CHANGELOG.
После существенного этапа создайте `YYYY-MM-DD-topic.md`; используйте дату
владельца проекта, а не произвольную дату хоста. Ссылки на коммиты добавляйте
только после их появления. Запланированное явно отделяйте от выполненного.

## Шаблон

```markdown
# YYYY-MM-DD — Тема
## Цель
## Исходная проблема
## Рассмотренные решения
## Принятое решение
## Реализация
## Проблемы
## Проверки
## Что я узнал
## Что можно улучшить
## Следующие шаги
```

Записывайте точные команды, итог, ограничения проверки и связь с кодом/ADR.
Не включайте секреты, персональные данные и придуманные истории успеха.
