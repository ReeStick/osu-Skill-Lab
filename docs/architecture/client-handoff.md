# Переход от разметки в локальный osu!

Status: Proposal; integration not implemented
Date: 2026-10-26

Владелец хочет выбирать карту в `/lab`, смотреть её в клиенте osu! на том же
компьютере и сразу возвращаться к разметке. На этом этапе запрошено только
рассмотреть решение. Кнопки запуска клиента, локального агента и чтения Songs
в продукте нет; конкретный установленный stable/lazer не проверялся.

## Что дают существующие ссылки

В [исторической документации ppy по osu://](https://github.com/ppy/osu-api/wiki#osu-url-schema)
`osu://edit/<time>[ (objects)]` описан как переход к времени/выделенным объектам,
без идентичности карты. `osu://b/<id>` и `osu://s/<id>` описывают osu!direct либо
переход на сайт. Из этого нельзя заключить, что такая ссылка выберет точный
локальный файл и откроет его в редакторе. Документация не заменяет проверку
поведения установленной версии клиента.

Уже существующая ссылка «На osu!» использует claimed ID файла, служит контекстом
и не является checksum verification. Для неизданных карт ID может отсутствовать;
для разных локальных редакций одинаковый claimed ID не определяет нужный файл.

## Предлагаемый следующий эксперимент

1. Зафиксировать установленный клиент и версию. Проверить поддерживаемые им
   URI/CLI/IPC для выбора локальной difficulty и перехода в редактор; отдельно
   проверить уже запущенный клиент. Не придумывать недокументированный URI.
2. Начать с явного действия пользователя «Открыть в редакторе». Если поддерживаемый
   протокол не позволяет выбрать точную карту, рассмотреть небольшой отдельный
   локальный helper с доступом к явно выбранной Songs-библиотеке.
3. Helper сопоставляет `LabRow.sha256` с локальными `.osu`, а не доверяет claimed ID
   и имени файла. При отсутствии точного файла сообщает об этом; не открывает
   похожую редакцию как ту же карту. Сами байты остаются локальными/временными,
   в API не передаются пути и не появляется постоянное хранилище исходников.
4. Проверить минимальный сценарий: точная редакция → editor → возврат к прежней
   карте в `/lab` → несколько явных human labels. Только после этого выбирать
   стабильный контракт интеграции. Local helper потребует отдельной установки
   пользователем и ограниченного канала взаимодействия с browser origin.

Это рабочая гипотеза реализации, не обязательство использовать helper и не
подтверждение доступности нужной команды в stable/lazer. Текущая UI доработка
не запускает клиент и не изменяет локальные карты.
