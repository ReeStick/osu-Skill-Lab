# Локальная подготовка .osz

Первый законченный срез M1 — извлечение `.osu` из локальных архивов.
Это CLI-операция без БД и HTTP. Parser и REST import пока не реализованы.

`.osz` — ZIP-архив beatmap set; `.osu` описывает отдельную difficulty.
Основание: [официальные форматы osu!](https://osu.ppy.sh/wiki/en/Client/File_formats).
Наличие локальных файлов не означает доступность массового скачивания через API;
сетевой импорт и актуальная документация API v2 будут исследоваться отдельно.

## Команда и результат

```powershell
uv run --locked osu-skill-lab extract-osz tests/unlabeled_osu_maps
uv run --locked osu-skill-lab extract-osz 'path/to/set.osz' --output-dir data/custom
```

При указании каталога команда обрабатывает только его `.osz`, без рекурсии.
В stdout выдаётся по одной JSON-строке на успешный архив; в stderr — JSON
ошибки. Exit 0: все архивы обработаны; 1: ошибки или пустой исходный каталог;
2: ошибка аргументов argparse. Ошибка одного архива не отменяет остальные.

```text
data/unpacked_osu_maps/
└── <archive-sha256>/
    ├── manifest.json
    └── 0000-<osu-sha256>.osu
```

Имена выходных файлов формируются сервисом, ZIP-пути используются только
как metadata. `manifest_version=1` и `extractor_version=1` фиксируют контракт.
Manifest содержит checksum/размер архива, происхождение `local_osz`, параметры
лимитов, имена исходных members, размеры/checksums `.osu` и число пропущенных entries.
Исходное имя архива выводится CLI, но не участвует в manifest и идентичности:
переименование того же архива не создаёт новый результат. URL загрузки и
турнирные labels не выводятся из имени файла и не придумываются.

Сначала создаётся ограниченная копия архива со streaming SHA-256, затем
временный каталог с результатом на том же filesystem. Только после чтения
всех выбранных файлов и проверки CRC каталог публикуется через rename.
Повторный запуск заново проверяет вход и сверяет manifest, размеры и SHA-256
всех результатов. Отличающийся существующий результат не перезаписывается.
Изменение политики лимитов также меняет manifest; для неё нужен другой output-dir.

## Лимиты и границы

| Ограничение по умолчанию | Значение |
| --- | --- |
| Размер `.osz` | 128 MiB |
| Число ZIP entries, включая ресурсы и каталоги | 10 000 |
| Число `.osu` | 256 |
| Размер одной `.osu` | 4 MiB |
| Общий размер выбранных `.osu` | 16 MiB |

Поддержаны ZIP STORED и DEFLATE для `.osu`; encrypted members, symlinks,
необычные file types, повторяющиеся имена без учёта регистра и опасные пути
отклоняются. Лимиты проверяются по metadata и фактически прочитанным байтам.
Аудио, storyboard, изображения и прочие ресурсы не распаковываются; их CRC
не проверяется. Ошибка во второй карте не публикует первую отдельно.

Отдельная временная копия обеспечивает соответствие checksum прочитанному входу
и требует до 128 MiB дополнительного места плюс выбранные `.osu`. `zipfile`
сначала читает central directory, затем доступна проверка числа entries;
это не жёсткий лимит памяти процесса. Для будущего недоверенного HTTP-upload
нужны отдельные ограничения запроса/процесса и выполнение вне HTTP event loop.

Output root задаётся оператором и должен быть доверенным; защита от конкурентного
административного изменения самого root не является контрактом этой команды.
Внутри существующего результата ссылки и лишние файлы не принимаются.
После аварийного завершения процесса может остаться `.extract-*`; обычные
ошибки очищаются через TemporaryDirectory. Автоматической уборки чужих файлов нет.

Распаковка сохраняет байты `.osu` и не подтверждает синтаксис, ruleset или
корректность hit objects. Все difficulty внутри архива извлекаются; проверка
osu!standard и формата относится к следующему parser-этапу.

Общие причины отказов ZIP и ограничения описаны в
[Python zipfile](https://docs.python.org/3.12/library/zipfile.html#decompression-pitfalls).
