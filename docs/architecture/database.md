# Данные и миграции

## Текущее состояние

PostgreSQL 17, SQLAlchemy 2.0 async с asyncpg, Alembic через `run_sync`.
Ревизия `0001_foundation` намеренно без DDL: единственная создаваемая таблица —
служебная `alembic_version`. Доменных сущностей пока нет.

`Base.metadata` задаёт имена PK/FK/unique/index/check constraints, чтобы
будущие миграции были предсказуемыми. Check constraints нужно явно именовать.
Сессии не разделяются между конкурентными задачами. Use case выполняет
`async with session.begin(): ...` либо явно `commit`; закрытие незавершённой
сессии откатывает транзакцию. Миграции запускаются отдельной командой,
не из startup и не через `create_all()`.

## Направление модели (пока не реализовано)

| Сущность | Назначение и ожидаемые ограничения |
| --- | --- |
| BeatmapSet / Beatmap | Локальные PK; внешние osu! ID nullable для unsubmitted карт, unique при наличии. Контрольная сумма файла и provenance обязательны |
| AlgorithmVersion | Неизменяемая версия алгоритма и схемы признаков; код/параметры воспроизводимы |
| AnalysisJob | Статусы, время, попытки, ошибки, lease/retry и ключ повторного запроса |
| AnalysisResult | Карта/версия исходника, нормализованные mods и их параметры, версия алгоритма, параметры анализа |
| SkillScore / MapSegment | Отдельные интерпретации признаков и результаты по временным сегментам |
| Tournament / MappoolEntry / Annotation | Контекст слотов, происхождение разметки, авторство и история |

На M1 будет выбран точный контракт версий исходников: внешние osu! ID и
checksum не взаимозаменяемы. Изменённый файл с тем же BeatmapID нельзя молча
считать уже обработанным. Unsubmitted карты не получают искусственный osu! ID.

Дедупликация анализа должна учитывать checksum, ruleset, канонические mods,
влияющие на расчёт mod settings, версию алгоритма и канонические параметры.
Ограничение уникальности в БД необходимо вместе с идемпотентным worker;
доставка сообщения не означает однократное выполнение.

Стабильные поля поиска и связей нормализуются. JSONB допустим для versioned
feature vectors и гибких параметров, но не заменяет FK/unique/status constraints.
Конкретная JSON-схема, индексы, transaction/outbox/lease стратегия пока не выбраны.
Время будет храниться с часовым поясом (UTC); migrations и модели добавляются
вместе с использующим их функционалом.

## Проверки

Интеграционные тесты требуют БД с суффиксом `_test`. Тест миграций запускает
upgrade, повторный upgrade, `alembic check`, downgrade и upgrade внутри случайной
схемы, затем удаляет только её. Тесты сессий проверяют commit и rollback в реальном
PostgreSQL. Они не доказывают корректность ещё не созданных таблиц и индексов.
