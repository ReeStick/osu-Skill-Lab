# ADR-0001: Модульный монолит и постепенное выделение границ

Status: Accepted
Date: 2026-10-25

## Context

Проекту нужны независимые алгоритмы и в перспективе отдельные workers,
но M0 ещё не содержит предметных операций. Пустые сервисы и множество
deployments усложнят разработку без проверяемой пользы.

## Decision

Один `src/osu_skill_lab` пакет. FastAPI собирается фабрикой, инфраструктура
отделена от транспорта. Application, Domain, Analysis и Workers добавляются
с конкретными сценариями. CPU-анализ не выполняется в HTTP event loop.
Очередь и worker будут выделены после базового импорта, без обещания надёжности
через FastAPI BackgroundTasks.

## Alternatives

- Микросервисы: отдельные контракты, deployments и отказы прежде первого сценария.
- Все операции в routes: быстро, но связывает математику с HTTP и затрудняет тесты.
- Полная clean architecture с пустыми ports/repositories: преждевременные контракты.

## Consequences

Небольшая структура и один runtime упрощают локальную работу. Границы модулей
нужно поддерживать ревью и тестами; физическая изоляция процессов появится позже.

## Revisit conditions

Независимое масштабирование, разные жизненные циклы компонентов или измеренные
ограничения монолита. Отдельный процесс worker сам по себе не требует микросервисов.
